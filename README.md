# 운명원 댓글 에이전트

유튜브 연애 영상을 불러와 → 고르면 AI가 영상 속 고민과 댓글 초안을 만들고 → 버튼 한 번에 크롬 프로필이 열려 한 글자씩 입력·게시·확인하는 로컬 대시보드입니다.

> 왜 이렇게 설계했는지는 [제작의도.md](제작의도.md)에 정리했습니다.

## 화면

| ① 영상 불러오기 | ② 영상 선택 | ③ 댓글 달기 |
|---|---|---|
| 연애 키워드 최신순 검색. '뜨기 직전 영상만'(기본 켜짐)이면 조회수 1,000~5,000 · 시간당 150회 이상만 표시. 링크 직접 입력 | 영상 속 고민 한 줄, 짚은 장면, 페르소나, 댓글 초안과 다른 후보 2개(수정 가능, 실시간 규칙 검사) | 프로필 선택/자동 배정, 진행 단계 표시, 댓글 보기 링크, 실패 사유와 스크린샷 |

아래에는 게시 기록(시간 · 영상 · 프로필 · 댓글 · 성공/실패)이 최신순으로 표시됩니다.

## 실행

1. **키 넣기**: `.env` 파일에 두 키를 넣습니다. (`run.bat`을 처음 실행하면 `.env`가 자동으로 생깁니다)
   - `ANTHROPIC_API_KEY`: [console.anthropic.com](https://console.anthropic.com) → Settings → API Keys
   - `YOUTUBE_API_KEY`: [Google Cloud Console](https://console.cloud.google.com)에서 YouTube Data API v3를 사용 설정한 뒤 API 키 발급
2. **`run.bat` 더블클릭**: 처음 실행하면 패키지를 설치하고, 브라우저에서 http://localhost:8000 을 엽니다.
3. **프로필 로그인 (최초 1회)**: ③의 `유튜브1` 옆 **[로그인]** 클릭 → 열린 크롬 창에서 구글 계정으로 로그인 → **창을 완전히 닫기**.
   유튜브2, 유튜브3도 같은 방법으로 다른 계정으로 로그인합니다(선택).

> 크롬 프로필은 `%LOCALAPPDATA%\unmyeongwon-agent\chrome-profiles\유튜브1` 같은 별도 폴더(`--user-data-dir`)에 만들어집니다.
> 평소 쓰는 크롬 프로필은 건드리지 않습니다. 자동 제어 중인 크롬에서는 구글 로그인이 막히는 경우가 많아서, 로그인만 일반 크롬 창으로 합니다.

## 설계

- **댓글 생성** (`app/ai.py`): 자막(없으면 제목·설명) + 인기 댓글 20개 → Claude가 ① 고민 한 줄 ② 짚을 장면 ③ 시청자 페르소나 ④ 말투가 다른 댓글 후보 3개를 쓰고, 그중 가장 사람 같은 것을 고릅니다(구조화 출력).
  - 장면을 요약하지 말고 반응하기, 말끝을 다양하게, AI 상투어 금지 같은 '사람 말투' 규칙을 프롬프트에 넣었습니다.
  - 최근에 만든 댓글을 함께 넣어 같은 문장 패턴이 반복되지 않게 합니다.
- **뜨기 직전 영상** (`app/youtube.py`): 5,000회 ÷ 시간당 150회 ≈ 33시간이므로 최근 36시간 영상만 봅니다.
  - 최신순만 보면 막 올라온 조회수 0~100짜리만 잡히므로, 관련도순 결과를 함께 모아 후보를 넓힌 뒤 조건으로 거릅니다.
  - 같은 검색은 10분간 캐시해 API 할당량을 아낍니다.
- **규칙 검사**: AI가 규칙을 지킨다고 가정하지 않고, 코드가 다시 검사합니다. 위반이 있으면 사유를 알려주며 다시 생성합니다(최대 3회).
  - 40~120자, 운명원 정확히 1회
  - 링크·해시태그 금지
  - 운명원을 이용해 본 것 같은 후기 표현("봤는데", "맞더라", "소름" 등) 금지
  - 광고 말투·AI 상투어 금지
  - 후보 3개 중 규칙을 통과한 것만 채택하고, 사람이 초안을 고쳐도 같은 검사를 거칩니다.
- **게시** (`app/poster.py`): Playwright `launch_persistent_context(channel="chrome")`로 진행합니다.
  - 영상(`hl=ko`)을 열고 댓글 창에서 한 글자씩 입력한 뒤 게시합니다.
  - 확인은 두 번 합니다. 먼저 댓글 목록에서 내 댓글을 찾고, 그 댓글의 고유 링크(`lc=`)로 다시 열어 한 번 더 확인합니다.
  - 실패하면 사유와 스크린샷을 저장합니다.
- **운영 규칙** (`app/db.py`): 서버가 규칙을 강제하고 SQLite에 기록합니다.
  - 영상당 1개(계정 1개), 하루 상한
  - 규칙 검사와 기록 생성을 한 번에 처리하므로 버튼을 연타해도 두 번 게시되지 않습니다.
  - 게시 버튼을 누른 뒤 확인에 실패한 경우는 실제로 달렸을 수 있으므로 '확인 필요'로 기록하고, 1개 규칙과 상한 계산에 포함합니다.

설정은 `config.yaml`에서 바꿉니다: 프로필, 글자 수, 일일 상한, 검색 키워드, 뜨기 직전 영상 조건, 모델.

## 사용한 오픈소스

FastAPI, Uvicorn, Playwright, youtube-transcript-api, httpx, PyYAML, python-dotenv, Pydantic, Anthropic Python SDK, Pretendard(폰트)
